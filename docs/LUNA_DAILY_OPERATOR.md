# Luna 日常监督对话

这个模式让 Luna 负责启动和观察，本地工作流与 BetterGI 继续负责实际执行。它不需要 OpenAI API Key，也不会把 Luna 放进战斗或逐帧识别循环。

## 新建对话设置

1. 在本仓库的本地项目目录下新建任务。
2. 模型选择 `GPT-5.6 Luna`，推理强度选择 `medium`。
3. 权限选择“完全访问”，以便触发本机计划任务并读取运行记录。
4. 只有需要查看或操作管理员权限的原神/BetterGI 窗口时，AI 客户端才需要具备同等级的桌面控制权限；正常启动和日志监督由最高权限计划任务完成。

不要修改全局默认模型。复杂代码修复仍应按证据升级到 Terra 或 Sol。

## 可直接发送的首条消息

> 开始今天的原神 core 日常。先检查 `GenshinDailyCore` 一键入口和当前运行状态，确认没有重复任务后启动。持续监控这次新 runId，正常运行时不要操作游戏画面。直到结果进入最终状态后再汇报 runId、总耗时、各任务结果、树脂使用、网络保护状态和手动画质是否恢复。若失败、部分完成或无法确认，先读取本次 `agent-context.json`，不得自动重跑或使用脆弱树脂；只给出一个有证据支持的恢复步骤。保持用户在 `networkGuardProcessNames` 中配置的网络服务运行。

## 运行边界

- `GenshinDailyCore` 是按需 Windows 计划任务，不带定时触发器。
- 关闭该对话不会终止已经启动的本地流程，但也不会继续由 Luna 在线监督。工作流仍会独立完成、停止或保存失败结果。
- 网络中断后重新进入对话，应先读取 `state/current-run.json`，不要直接启动第二次。
- 若运行器已经结束但画质恢复凭据仍为待处理状态，应确认原神已退出，再执行 `python scripts/workflow.py restore-graphics`。
