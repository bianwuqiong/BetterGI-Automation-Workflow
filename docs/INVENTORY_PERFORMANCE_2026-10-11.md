# 新机开发：库存读取与游戏日边界（2026-10-11）

本轮保持新机只读、零预算、资源适配未授权。以下改变用离线假接口回归验证，没有启动游戏、刷怪或消费树脂；没有移植旧机器凭据、授权、库存或网络规则。三个历史正常批次共 37 分 48 秒仍是当前公开性能基准，尚无新的全流程实测时间，不能声称已达到约 20 分钟。

## 已修复的重复读取

`AutoGameCultivation/core/operator.js` 原先将同一运行中已核实的背包材料身份标为优先提示，却仍先调用通用图标库存读取，再转入完整材料名与选中堆叠数量的原生读取。指南身份已有真正的优先路由；背包身份缺少同等优化。

现在只将已核实身份用于选择读取路径，先为这些材料获取新的原生双帧证据。只有本次新帧同时核实完整名称、选中数量和主界面恢复的行才从通用图标请求中排除。没有复制旧数量，每笔消费后的 `after` 仍读取完整材料链；后一步 `before` 的同 run 复用仍受最早观察起点 120 秒、相邻成功步骤、同秘境及同奖励选择约束。

失败不降低核验标准：原生两次干净未命中仍为未知，通用图标数量不能顶替曾要求的具名材料证据；重新核实的指南双帧可补充证据。原生异常、未核实恢复或不合法来源不进入另一个界面、不再重试，也不执行资源任务。

离线场景可量化请求变化，但不是实机秒数：

- 一个完整四级武器材料链中，铁链需具名背包读取、最高级条目需指南读取时，初始／新 `before`／新 `after` 的通用请求从 `4/3/3` 行变为 `4/2/2` 行；两次新读取仍分别取得新具名证据。
- 当四行全部能被本次新具名背包或指南证据覆盖时，后续 `before` 和 `after` 无需重新打开通用图标库存；完整链和新 `after` 仍保留。
- 失败、过期、跨 run、非相邻、未知或变更来源的路径继续停止或重新读取，不靠减少证据实现提速。

## UTC+8 凌晨 4 点边界

原有 120 秒复用可能跨越游戏日重置。现在拒绝跨 UTC+8 04:00 的来源读取或跨日 run 的复用；每日执行在循环、准备完成、持久化前和资源接口进入前检查游戏日。重置发生在持久化之后时，保留已写的 `unknown` 步骤，不调用消费接口、不重放。

已经在重置前开始并核实的单步仍收集新的 `after` 和树脂证据；之后停止新步骤。这不自动取得新一天的授权。Python 对协议的独立日期核验由工作流端另外实现。

仍需引擎级边界：资源接口在重置前进入，实际领奖可能在重置后发生。JavaScript 的接口前检查只能约束入口，不能证明引擎内实际提交时间；应在原生受保护领奖点检查游戏日或以重置时间限制取消令牌，并保留提交后的未知状态。这不是已通过的新机实机验收。

## 后续开发方向与验收边界

- 现有 `cultivation` 档可在一次 BetterGI 启动中安排邮件、培养材料和每日奖励，且每日培养已能在一个 run 中逐笔执行。应优先使用这个路径衡量完整时间，再决定是否需要新的多批次宿主；跨 run 库存和授权不能直接复用。
- `scripts/workflow.py` 已按当天独立成功证据跳过完成的其他节点，同时刻意不给培养节点继承旧扫描。保留这项安全边界；优化前应分别量出启动、档案、每类库存、每轮战斗、核验和退出／画质恢复时长。
- 派遣仍应核验原生领取与重新派遣的独立证据，不能因“每日奖励”节点返回就宣称派遣成功。交接仍明确每日派遣重置尚未验收，应建立本机夹具并检查新派遣状态，再扩展验收。
- 刀镡连续战斗、实际升级及路线当日总产出仍需独立验收与后续授权。谜主材料已够的用户约束应继续阻止这类来源，不以当前优化开启任何适配。

## 离线验证

执行 `node --test bgi-scripts/AutoGameCultivation/tests/*.test.js`。本轮培养测试 **150 项通过、0 失败**；新增覆盖原生优先路由、全部具名行省去通用界面、原生失败不能降级为图标数量，以及重置发生在准备、checkpoint 和相邻步骤之间的边界。测试使用假游戏接口，不能替代本机只读识别、派遣或新全流程时长验收。
