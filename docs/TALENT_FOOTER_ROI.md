# 天赋预检的完整材料数量与安全收尾

2026-10-13 修改继续复用固定 BetterGI 基线的 `ReadWholeFooter`、天赋页面 Reader 和只读清理策略。没有增加新的 OCR 模型或消费入口。

## 完整材料 footer

`existing_full_footer_v2` 将完整文字区域固定为 `(882,875,223,80)`。此前 `(725,890,470,65)` 在部分材料页裁掉文字顶部，也包含文字左侧的状态图标。新区域依据保留截图的实际完整文字框确定；原图仍为 1920×1080，没有缩放、补造像素或修改数字。

每帧继续读取完整“培养需求”前缀和 `持有量/培养总需求`，要求原始识别与检测行一致、唯一完整行、四边至少 2px。两帧数量与材料身份一致，原 1500ms 配对接受门槛不变。培养总需求与当前单次升级费用分别读取，不能互相替代。

v2 必须同时保留两组同帧诊断：旧窄区域 `(885,890,295,65)` 的 `initialReading`，以及旧完整区域 `(725,890,470,65)` 的 `originalWholeReading`、`originalWholeRawText` 和 `originalWholeDetectorText`。失败原读数仍为失败，数量保持 null；任何独立已完成读数都必须与新读数一致。原始完整 PNG 与模型证据继续由 Host 复核。

`existing_full_footer_v1` 保持原区域及原字段契约，禁止混入 v2 字段。一次 payload、同一配对不得混用版本。新版本不会将旧 unknown 批次改为成功。

新版本的第二路名称读取继续使用同一名字区域及 4x cubic 放大，保留原色，要求真实原始识别与唯一检测行完整同名、四边 2px；此前阈值预处理会在部分字上造成识别错误。独立原尺寸名字读取仍必须完整同名。“来源”区域改为 `(730,675,460,80)`，补足原顶部裁边。`originalIdentityReading` 必须保留同帧旧阈值名称结果及原 `(730,690,460,65)` 来源行，即使旧名误读或旧框边距不足；这些诊断不参与新身份接受。固定模型和身份标准保持。

## 安全返回大世界

清理复用现有页面识别与 `InspectionCleanupPolicy`，只按已识别层调整下一帧的读取顺序，避免每帧重复执行不相关的大区域 OCR。缓存只决定读取顺序，不能证明当前页面；任何输入仍需当前完整页面的独立双帧证明，未知页面不输入。

原十秒观察期限、每层最多一次 Esc、前台检查和大世界完整谓词保留。连续两张新鲜大世界截图通过配对后，才保存两张原尺寸 PNG，并记录原截图时钟、配对时钟和诊断写盘时钟。诊断写盘不延长观察或输入期限，也不能刷新截图时钟。PNG 或解码像素回读失败仍不能宣称完整收尾。

## 验证范围

固定新区域在两种材料的四张保留原图上，使用真实固定模型及现成 `ReadWholeFooter` 离线复读均通过；独立 V4 读取也一致。此结果只证明取图修复，不能作为新的实机库存或已完成升级证据。当前构建、回归及新实机预检结果以独立验收记录为准。

本入口始终只读，不提交“确认”，不消费摩拉、材料或树脂。实际升级需要另一个有效消费授权及完整事务验证。
