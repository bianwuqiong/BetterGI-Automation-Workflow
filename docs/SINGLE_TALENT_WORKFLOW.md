# 单项天赋培养：先复用，再补缺失操作

首个可用里程碑是一项基础天赋的可靠升级。BetterGI继续负责角色定位、天赋与费用读取、材料获取和既有合成；本项目只补操作连接及结果核验。全量八种库存、三项天赋和武器费用不会统一成为首次升级的前置条件。

## 已接入的单项范围派生

现有 `--cultivation-talent-preview --talent-type elemental-skill` 等入口仍是零预算只读。JS只有在既有完整预览验证通过后才生成 `singleTalentNextStep`；Host先独立验证原始角色、天赋、等级、费用、材料完整名称和恢复证据，再按本地静态材料目录重新计算并逐项比较该计划。

该计划仅列所选天赋下一基础等级的投入材料、摩拉和数值缺口，并生成可传给既有具名库存读取器的材料ID/完整名称scope。scope中没有caller库存、费用、进程绑定、批准或消费许可。名称不能唯一映射、数量未知或重复材料时拒绝生成有效计划，不能补零。计划不表示库存对未来消费仍新鲜，也不代替单次提交门禁及独立费用前后核对。

所选天赋已达到配置目标时，不建议继续升一级，不生成材料扫描scope，也不声称其他天赋、角色或武器目标已经完成。更换目标角色或目标天赋等级沿用同一派生逻辑，不以第二个角色的真实消费作为参数化测试。

## 尚未完成的实际升级路径

只读预览中的角色身份是历史读取，不足以证明最终确认前仍处于同一角色/同一天赋。原始升级弹窗没有角色全名，需要复用受控取消、完整header/所选条目/detail核验和重开动作，形成同一owned capture session的连续证据，然后读取新的最终双帧。

相关原生实现仍在私有隔离候选中，消费入口默认关闭。实际升级必须使用有效本机授权、真实同进程一次提交、当前费用与库存，并独立核对基础等级+1及全部投入资源/摩拉的实际变化。unknown不重放，既有1500ms门禁不放宽。

没有取得实机完整预览或真实升级通过证据时，只报告未完成。游戏登录由用户在本机处理；缺少登录不会阻止独立离线开发。原消费窗口过期后，本计划不创建或延长新的消费授权。
