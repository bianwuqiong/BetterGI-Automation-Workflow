# 2026-10-11 本机迁移启动修复

首轮只读实机已显示大世界，但原生启动识别等待未结束，未开始任何任务节点。停止后退出与手动画质恢复核验完成；这轮不计只读扫描通过，也未进行消费。

检查发现 Windows 11 的 BitBlt 兼容注册表设置原先在截图器启动时才写入。该设置要求在创建游戏进程之前生效；首轮写入时间晚于游戏窗口稳定出现。现有证据确定时序缺陷，但没有原生捕获帧，不能仅凭推断认定黑帧或主 UI 模板失配。

## 代码与行为

- `HomePageViewModel.OnStartTriggerAsync` 在原神关联启动前同步核验 BitBlt 设置，失败不创建游戏进程。
- `BitBltRegistryHelper` 仅合并 `SwapEffectUpgradeEnable=0`，保留其他 GPU 偏好且幂等；现有截图器和主窗口调用同样采用该合并方法。
- `ScriptService.StartGameTask` 从关联启动前开始累计单调时间，正常启动路径已有 120 秒窗口出现上限；UI 等待、截图器初始化与仓库更新共用 180 秒总期限。超时不返回成功。一条龙和配置组入口捕获失败，记录“启动核验失败，未执行任务节点”，不进入节点循环。
- 沿用主 UI（含复活弹窗排除）、可关闭 UI、秘境判断；没有修改 Paimon 模板、匹配阈值或成功条件。
- 默认诊断只包含捕获模式、尺寸、帧数、像素均值/标准差、匹配布尔值与时序，不自动保存界面图像。后续若需区分捕获问题与模板问题，须先由本机 UI 确认大世界后另行采集私人游戏帧。

该兼容键是本机窗口捕获设置，不属于原神手动画质白名单。保留原神默认亮度、窗口 1920×1080、极低画质和现有保存/恢复机制；没有修改系统代理、规则或 TUN。
